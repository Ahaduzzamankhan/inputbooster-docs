<Lead>
The repository is not a single loader-neutral project. It contains separate Fabric Gradle projects for the supported Minecraft lines, with the 26.2/26.3 implementation in <code>fabric/</code>.
</Lead>

## Project layout

| Directory | Target | Role |
| --- | --- | --- |
| <code>fabric/</code> | 26.2 and 26.3 | Main 4.1.2 implementation, with per-version compatibility sources |
| <code>fabric-26.1/</code> | 26.1 | Separate 4.1.2 Fabric project |
| <code>fabric-26.1.2/</code> | 26.1.2 | Separate 4.1.2 Fabric project |
| <code>fabric-1.21.1/</code> | 1.21.1 | Separate 3.1.5 legacy project |
| <code>fabric-1.21.4/</code> | 1.21.4 | Separate 3.1.5 legacy project |
| <code>fabric-1.21.11/</code> | 1.21.11 | Separate 3.1.5 legacy project |

The current branch is Fabric-only. The NeoForge project, metadata, entrypoint and loader abstractions that existed only for NeoForge have been removed.

The 1.21.x directories are independent older project trees. Do not assume a change in <code>fabric/</code> automatically changes those artifacts; the release matrix builds and tests each directory separately.

## Main 26.2/26.3 packages

The main implementation lives under <code>fabric/src/main/java/dev/inputbooster</code>.

| Area | Responsibility |
| --- | --- |
| <code>engine</code> | Engine modes, compatibility resolution, diagnostics and configuration access |
| <code>input</code> | Physical state, keyboard/mouse processors, routing and event dispatch |
| <code>feature</code> | CPS limiter, movement helpers, replay, profiles, click feedback and overlay |
| <code>command</code> | Client-side <code>/inputbooster</code> command |
| <code>screen</code> | Vanilla fallback settings screen |
| <code>compat/sodium</code> | Optional Sodium Config API entrypoint and pages |
| <code>compat/modmenu</code> | Optional Mod Menu entrypoint |
| <code>mixin</code> | Client observers, tick drain and options/HUD hooks |
| <code>access</code> | Duck/accessor interfaces used by mixins |

## Input path

~~~text
GLFW key state ---------------------+
                                    |
KeyboardHandlerMixin ---------------+--> InputEngine
MouseHandlerMixin ------------------+        |
                                             v
                                      bounded action queue
                                             |
                                   GameTickMixin at tick HEAD
                                             |
                                         InputDrainer
                                             |
                                  guarded vanilla client calls
~~~

The polling thread observes raw platform key state. Keyboard and mouse mixins observe events without cancelling them. The engine merges state edges and queues actions; the game-thread drainer performs the action and suppresses a duplicate vanilla attack or use only for the tick it handled.

## Engine and compatibility

The engine supports automatic, event and poll modes. The compatibility manager queries Fabric Loader by mod id for four known input-routing mods: Controlify, Midnight Controls, Controllable and Zoomify. Sodium and Iris are rendering mods and are not in that list.

If the event hooks are unavailable, or automatic compatibility fallback is triggered, the engine uses polling. The vanilla handlers remain in place.

## Configuration and optional UI

<code>InputBoosterConfig</code> owns the properties file and the defaults. The vanilla options screen is always the fallback route. On 26.x, the optional Sodium Config API registers four pages; Mod Menu can open the vanilla screen.

The profile manager and per-server profile loader remain in the feature package, but the current player-facing settings screens do not expose profile save/load/delete controls.

## Version-specific code

The <code>fabric/</code> project keeps 26.2 and 26.3 differences in its compatibility source sets. The other Minecraft lines are separate Gradle projects with their own version-specific source and metadata. See [building and testing](/docs/developers/building-and-testing) for the build matrix.
