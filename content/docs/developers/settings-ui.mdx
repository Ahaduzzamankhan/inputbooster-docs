<Lead>
The old custom window and its separate profile screen have been removed. The current UI has an optional Sodium Config API entrypoint and a vanilla screen used as the fallback.
</Lead>

## Entry points

| Entry point | When it is available | Opens |
| --- | --- | --- |
| Sodium Config API | 26.x builds when a compatible Sodium release is installed | Four native pages in Sodium Video Settings |
| Options screen button | All current builds | <code>InputBoosterVanillaScreen</code> |
| Mod Menu | When Mod Menu is installed | <code>InputBoosterVanillaScreen</code> |

The 1.21.x projects do not declare the Sodium Config API entrypoint. Their supported settings route is the vanilla screen.

## Sodium integration

The 26.x project keeps Sodium API references in the optional compatibility package. The entrypoint registers four pages:

- **General:** polling, engine mode and compatibility fallback.
- **Features:** movement helpers, combo keys, CPS limiter and burst mode.
- **Overlay:** visibility, placement, appearance and diagnostics.
- **Advanced:** input handling, safety, replay, profiles and click feedback.

Sodium is not bundled into the jar. The build compiles against the Config API as a compile-only dependency and verifies that Sodium and Mod Menu classes are not packaged. If the optional integration cannot link at runtime, the mod logs the integration failure and retains the vanilla settings route.

The option storage handler writes to the same <code>InputBoosterConfig</code> persistence layer as the fallback screen. Reset-to-default values come from <code>InputBoosterConfig.Defaults</code>.

## Vanilla fallback screen

<code>InputBoosterVanillaScreen</code> uses vanilla buttons, cycle controls and sliders. Its six sections are Polling, Input engine, Movement assistance, Click limiter, Overlay, and Safety and feedback.

Controls save their values when changed. There is no custom window geometry, tab rail, Save & Close action or separate profile-management screen.

The Options screen mixin adds the InputBooster button. The Mod Menu entrypoint opens the same fallback screen when that mod is installed.

## Profile behavior

<code>ProfileManager</code> still supports profile capture, apply, save and delete operations internally, and <code>PerServerProfileManager</code> can load a bound profile. No current player-facing settings screen or client command calls the profile save/load/delete methods. The JSON profile file and server binding properties file therefore remain manual configuration surfaces.

## Implementation rules

- Keep optional Sodium classes isolated from the common vanilla screen.
- Do not make Sodium a required dependency.
- Use <code>InputBoosterConfig.Defaults</code> as the single source of reset values.
- Save changes through the existing config persistence layer.
- Keep the vanilla screen functional when Sodium or Mod Menu is absent.
