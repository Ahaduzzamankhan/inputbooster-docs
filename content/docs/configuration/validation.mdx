<Lead>
A broken config value costs you that one setting and nothing else. This page
documents the current 306 schema used by both the 4.1.2 26.x and 3.1.5 1.21.x
projects.
</Lead>

## The load order

<Steps>
  <Step title="Reset to the documented defaults">
    Every field is set back to its default before the file is read. Nothing
    survives from the previous session unless the file says so.
  </Step>
  <Step title="Read the file">
    The file is parsed as a Java properties file. A file that does not exist
    causes the defaults to be written out instead.
  </Step>
  <Step title="Migrate">
    If the schema version is older than 306, the legacy-key migration runs and
    the version is updated to 306.
  </Step>
  <Step title="Apply and clamp">
    Each key is parsed and clamped into its allowed range where a range exists.
  </Step>
  <Step title="Report">
    Keys covered by the validation list that could not be used are collected
    and named in one warning line. Some other parsed keys fall back silently.
  </Step>
</Steps>

## Booleans

Seven spellings are accepted, in any case:

<code>true</code>, <code>yes</code>, <code>1</code>, <code>on</code> are true.
<code>false</code>, <code>no</code>, <code>0</code>, <code>off</code> are false.

Anything else falls back to the default. The comparison trims surrounding
whitespace first, so <code> true </code> is valid.

## Numbers

An integer that cannot be parsed falls back to the default. A parsed value
outside the allowed range is clamped:

| Key | Below range | Above range |
| --- | --- | --- |
| <code>poll_rate_hz</code> | 60 | 1000 |
| <code>max_cps</code> | 1 | 20 |
| <code>overlay_position</code> | 0 | 4 |
| <code>fps_check_interval</code> | 1 | 100 |
| <code>engine_mode</code> | 0 | 2 |
| <code>mouse_scroll_debounce_ms</code> | 0 | 200 |
| <code>mouse_click_dedupe_ms</code> | 0 | 100 |
| <code>overlay_mode</code> | 0 | 1 |
| <code>overlay_scale</code> | 0.5 | 3.0 |
| <code>overlay_opacity</code> | 0.0 | 1.0 |
| <code>click_sound_pitch</code> | 0.5 | 2.0 |
| <code>click_sound_volume</code> | 0.0 | 1.0 |

<code>overlay_color</code> is parsed as a signed decimal integer. It is not
clamped to a palette; invalid text falls back to the default. Do not use a
<code>0x</code> prefix in the properties file.

## The warning line

~~~text
Config entries reset to defaults (invalid or unparsable): poll_rate_hz=2000, combo_keys=maybe
~~~

A boolean is listed by name. A number is listed as <code>key=value</code> so
you can see what was actually in the file.

<Callout variant="note" title="One line, not one line per key">
The report is a single warning listing every key that had to be reset. It is
logged once per load, right before the "config loaded successfully" line.
</Callout>

## Which keys are checked

These keys are validated and reported when they are bad:

**Booleans:** <code>poll_rate_auto</code>, <code>sprint_fix</code>,
<code>auto_sprint</code>, <code>wtap_assist</code>, <code>anti_idle</code>,
<code>auto_strafe</code>, <code>cps_limiter</code>, <code>burst_mode</code>,
<code>combo_keys</code>, <code>custom_keyboard_handler</code>,
<code>keyboard_repeat_guard</code>, <code>compat_fallback</code>,
<code>overlay_show_engine</code>, <code>overlay_show_events</code>,
<code>overlay_show_overhead</code>.

**Numbers:** <code>engine_mode</code>, <code>mouse_scroll_debounce_ms</code>,
<code>mouse_click_dedupe_ms</code>, <code>overlay_mode</code>,
<code>poll_rate_hz</code>, <code>max_cps</code>, <code>overlay_position</code>,
<code>fps_check_interval</code>.

<code>overlay_test_rect</code> is parsed as a boolean but is not in the warning
list. <code>overlay_color</code> is parsed as an integer but is not in the
warning list either.

<Callout variant="warning" title="Checked is not the same as used">
Two inert settings are validated but still do not affect runtime behavior:
<code>keyboard_repeat_guard</code> and <code>fps_check_interval</code>. The other
three inert keys (<code>show_keystrokes</code>, <code>debug_mode</code> and
<code>click_sound_volume</code>) are not in the validation list.
</Callout>

## Which keys are not checked

These are not in the validation list. A bad value still falls back to the
default, but it is not named in the warning line:

<code>click_sounds</code>, <code>click_sound_pitch</code>,
<code>click_sound_volume</code>, <code>replay_enabled</code>,
<code>safe_mode</code>, <code>event_log</code>, <code>key_conflict_warn</code>,
<code>per_server_profiles</code>, <code>show_f3_info</code>,
<code>show_keystrokes</code>, <code>show_action_bar</code>, <code>debug_mode</code>,
<code>overlay_color</code>, <code>overlay_test_rect</code>, <code>cps_mode</code>,
<code>config_version</code>.

## Strings

<code>cps_mode</code> is sanitized to one of <code>FIXED</code>,
<code>HUMANIZED</code>, <code>WEAPON_AWARE</code> or <code>COOLDOWN</code>.
A null or unknown value becomes <code>FIXED</code>. This fallback is silent:
the bad string is not included in the warning line.

## Migration

Older schemas are migrated in place. The migration renames three keys:

| Legacy key | Current key |
| --- | --- |
| <code>auto_sprint_key</code> | <code>auto_sprint</code> |
| <code>watap</code> | <code>wtap_assist</code> |
| <code>pollrate</code> | <code>poll_rate_hz</code> |

A rename only happens when the current key is absent, so a file that already
has the new key keeps its own value.

<Callout variant="note" title="The migration is deliberately small">
Schemas 1 through 303 used the same key names and had no upgrade path. Schema
305 is upgraded to 306. The migration does not invent values or change feature
semantics; it only renames the three keys that were spelled differently in
very old builds.
</Callout>

## What a broken file cannot do

| Situation | Result |
| --- | --- |
| The file does not exist | Defaults are written out |
| The file is not readable | A warning is logged and the defaults are used |
| A value is unparsable | That key is reset; the rest of the file is applied |
| A value is out of range | It is clamped into range |
| A key is missing | The default is used for it |

There is no state in which a bad config file prevents the game from starting.
