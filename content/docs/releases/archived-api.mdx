<Lead>
There are two repositories with the InputBooster name. The mod and this
documentation come from one. The API is a separate, archived project that is
not connected to the current tree.
</Lead>

## Its status

The API repository's own README opens with the conclusion:

```text
InputBooster API - No Longer Maintained

> Maintenance has ended. This repository is no longer actively developed
> or supported. It is preserved for reference only.
```

<Callout variant="danger" title="Do not build against it">
A dependency on `dev.inputbooster:inputbooster-api:3.1.0` will not work with
the 4.1.x mod. The API targets Minecraft `>=1.21 <1.22`; the mod targets 26.2
and 26.3. There is no bridge between them.
</Callout>

## What it targeted

| Property | The archived API | The current mod |
| --- | --- | --- |
| Minecraft | `>=1.21 <1.22` | 26.2 and 26.3 |
| Java | 21+ | 25 |
| Loader | Fabric only | Fabric and NeoForge |
| API version | `3.1.0` | — |
| Status | Archived, unmaintained | Active, alpha |

## What it offered

The API exposed live statistics, configuration controls, profile helpers,
latency metrics and an event listener surface, without forcing dependent mods
to require InputBooster at runtime.

Its own quick-use example:

```java
if (InputBoosterAPI.isLoaded()) {
    InputBoosterAPI api = InputBoosterAPI.getInstance();
    int hz = api.getPollRateHz();
    api.setAutoMode(true);
}
```

And a snapshot helper for HUD and debug overlays:

```java
InputBoosterStats.snapshot()
```

## How it was meant to be wired in

The API's maintainer notes describe the integration as a manual step:

```text
Copy impl-stub/java/dev/inputbooster/api/impl/InputBoosterAPIImpl.java
into the main InputBooster mod source tree and register it after
initialization.
```

<Callout variant="warning" title="That step was never performed">
The current source tree contains no `dev.inputbooster.api` package, no
`InputBoosterAPI` class and no `InputBoosterAPIImpl`. The implementation
stub was never merged into the 26.x tree.
</Callout>

## Why it is not connected

| Reason | Detail |
| --- | --- |
| The Minecraft version moved | The API is pinned to 1.21.x. The mod is 26.2 and 26.3 |
| The Java version moved | The API needs Java 21. The mod needs Java 25 |
| The engine was rewritten | The 4.1.0 engine introduced `InputEngine`, a new state machine and new diagnostics. The API's surfaces do not map onto it |
| Maintenance ended | The repository states it should not be assumed to receive compatibility updates |

## What to use instead

| You want to… | Use |
| --- | --- |
| Read live input statistics | The overlay and the Overview tab of the settings screen |
| Change a setting from another mod | The config file, or the settings screen |
| React to input events | There is no public event API in 4.1.2-alpha |
| Build a profile | The profiles screen and `inputbooster_profiles.json` |
| Read the latency figures | The profiler and the session statistics |

<Callout variant="info" title="An honest gap">
The current mod has no supported way for another mod to observe its input
events. If you need that, the options are to contribute a listener surface to
the mod, or to read the diagnostics counters. The
[contribution guide](/docs/contributing/workflow) covers the first option.
</Callout>
