<Lead>
The current interface is not the old movable seven-tab window. On 26.x, compatible Sodium builds expose four native configuration pages. The vanilla fallback screen is also available from Options and Mod Menu.
</Lead>

## Open the settings

- **Options:** open Minecraft Options and select the InputBooster button.
- **Mod Menu:** use the InputBooster configuration entry when Mod Menu is installed.
- **Sodium on 26.x:** open Sodium's Video Settings and select InputBooster in the sidebar.

The 1.21.x artifacts do not declare the Sodium Config API entrypoint. Use the vanilla options screen or Mod Menu for those builds, even when Sodium is installed.

## Sodium pages on 26.x

| Page | Main controls |
| --- | --- |
| General | Automatic/manual polling, engine mode, compatibility fallback |
| Features | Sprint fix, auto sprint, W-tap, anti-idle, auto strafe, combo keys, CPS limiter, maximum CPS, limiter mode, adaptive burst |
| Overlay | F3 information, keystroke toggle, action-bar messages, display mode, position, opacity, scale, colour, test rectangle and diagnostics |
| Advanced | Keyboard repeat guard, scroll debounce, click deduplication, experimental keyboard handler, safe mode, event logging, key warnings, debug mode, FPS interval, replay, per-server profiles and click sounds |

Sodium uses its Config API widgets and writes changes through the same configuration store as the vanilla screen.

## Vanilla fallback screen

The fallback screen is built from vanilla controls. It has six scrollable sections:

1. **Polling** — automatic polling, manual frequency and FPS check interval.
2. **Input engine** — engine mode, compatibility fallback, repeat guard, mouse debounce and experimental keyboard handler.
3. **Movement assistance** — sprint fix, auto sprint, W-tap, anti-idle, auto strafe and combo keys.
4. **Click limiter** — enable/disable, maximum CPS, limiter mode and adaptive burst.
5. **Overlay** — visibility, display mode, position, scale, opacity, colour, test rectangle, keystrokes, action-bar messages and diagnostic lines.
6. **Safety and feedback** — safe mode, event log, conflict warnings, debug mode, replay, per-server profiles and click sounds.

There is no movable/resizable custom window, tab rail or Save & Close button in this version. A change is saved as its control is changed.

## Overlay positions and colour

The overlay supports five positions: top-left, top-right, bottom-left, bottom-right and top-center. The colour control offers White, Cyan, Green, Yellow, Orange, Red, Magenta and Grey. The configuration file can store a custom ARGB integer, even though the UI presents presets.

The test rectangle is a diagnostic aid for confirming the overlay's position and visibility. It is not a gameplay indicator.

## Settings that are not fully implemented

The UI still exposes a few persisted settings that have no runtime effect. In the current source, these are:

- <code>show_keystrokes</code> — no keystroke renderer is present.
- <code>click_sound_volume</code> — the click sound manager uses pitch but does not apply this volume setting.
- <code>fps_check_interval</code> — stored and displayed, but not read by the adaptive poll-rate logic.
- <code>keyboard_repeat_guard</code> — GLFW repeat events are ignored unconditionally; this setting does not gate that behavior.
- <code>debug_mode</code> — persisted but does not currently gate debug logging.

See [key reference](/docs/configuration/keys) and [limitations](/docs/reference/limitations) for details.

## Profiles

The profile manager and per-server profile loader still exist, but the current settings screens do not expose Save, Load or Delete controls. Profiles and server bindings must be prepared in their JSON/properties files; see [Profiles](/docs/guide/profiles).
