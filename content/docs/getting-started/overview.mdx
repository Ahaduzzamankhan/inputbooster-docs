<Lead>
InputBooster is a client-side Fabric mod that observes keyboard and mouse input between Minecraft ticks. It preserves a short physical press that begins and ends between two ticks, then drains the resulting action on the client tick.
</Lead>

Minecraft normally processes much gameplay input on a 20 Hz tick. A short tap can begin and end inside one 50 ms tick window, so the tick never sees the press. InputBooster combines high-rate polling with keyboard and mouse event observers, converts state changes into actions, and drains them through guarded vanilla client calls.

The mod is not an autoclicker. It does not create input without a physical press, extend reach or send its own network packets.

## Current release

The current published tag is <code>v4.1.2-beta3</code>. The four 26.x artifacts report mod version 4.1.2. The three 1.21.x artifacts report 3.1.5 and are built from separate older project trees.

All current artifacts are Fabric client mods. NeoForge support has been removed.

## The input path

~~~text
Platform key state / keyboard and mouse events
                    |
              InputEngine
                    |
          bounded action queue
                    |
        InputDrainer at tick HEAD
                    |
           vanilla client calls
~~~

The event hooks observe input; they do not replace vanilla's keyboard or mouse handlers. The drainer suppresses a duplicate vanilla attack or use only when InputBooster already handled that action for the same tick.

## What it does

- Samples bound keyboard and mouse state at a configurable rate.
- Uses event hooks when available and resolves between automatic, event-driven and polled modes.
- Queues physical input edges and drains them on the client thread.
- Provides movement assistance, a CPS limiter, replay recording, diagnostics and an optional HUD overlay.
- Offers native Sodium configuration pages on the 26.x builds when a compatible Sodium Config API is present.
- Provides a vanilla options screen as the fallback configuration interface.

## What it does not do

- It does not generate clicks, movement or aim without physical input.
- It does not extend vanilla melee reach or change server-side hit validation.
- It does not replace the vanilla input handlers or send custom gameplay packets.
- It does not guarantee an FPS or latency improvement. The repository does not publish a client benchmark.
- It does not include a server-side component.
