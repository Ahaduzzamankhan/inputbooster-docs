<Lead>
Installation is one jar in one folder. The only real decision is which jar:
pick the one whose `mc262` or `mc263` suffix matches your Minecraft version and
your loader.
</Lead>

## Before you start

- [Requirements](/docs/getting-started/requirements) — confirm Java 25 and your
  loader version.
- [Jar matrix](/docs/installation/jar-matrix) — the full table of published
  jars and their version ranges.

## Install

<Steps>
  <Step title="Pick exactly one jar">
    Match the `mc262` or `mc263` suffix to your Minecraft version and the loader
    name to your loader. Never install two InputBooster jars at once — both
    register the same key mappings and the same mixins, and the client will
    crash during class transformation.
  </Step>
  <Step title="Copy it into the mods folder">
    The folder is the `mods` directory inside your Minecraft installation. On the
    official launcher it is the one with the `versions` folder next to it.
  </Step>
  <Step title="Start the client">
    Launch Minecraft. The mod is client only, so join a world to test it; the
    settings button is on the options screen, not in a server list.
  </Step>
  <Step title="Check the log">
    Look for the ready line. If it is missing, the mod did not load.
  </Step>
</Steps>

<Callout variant="danger" title="One jar per profile">
`inputbooster-4.1.2-alpha-fabric-mc262.jar` and
`inputbooster-4.1.2-alpha-fabric-mc263.jar` are different builds of the same
mod. Installing both puts two copies of `GameTickMixin` and two
`KeyboardHandlerMixin` into the same class, which fails the client at startup.
</Callout>

## Fabric

Fabric needs three things in `mods`: the InputBooster jar, Fabric API, and any
other mods you use.

<Command command=".minecraft/mods/inputbooster-4.1.2-alpha-fabric-mc263.jar" block label="Fabric 26.3" />

<Command command=".minecraft/mods/inputbooster-4.1.2-alpha-fabric-mc262.jar" block label="Fabric 26.2" />

## NeoForge

NeoForge has no separate API jar. The mod goes in the same `mods` folder.

<Command command=".minecraft/mods/inputbooster-4.1.2-alpha-nf-mc262.jar" block label="NeoForge 26.2" />

## Verify it loaded

The mod prints a ready line during initialisation. Open the log file and look
for it:

<Command command=".minecraft/logs/latest.log" block label="The log the mod writes to" />

```text
[InputBooster] Starting v4.1.2-alpha
[Mixin] All client hooks present.
[Mixin] Screen hooks: setScreenAndShow=true, setScreen=false
[inputbooster-config] Loading config from .../config/inputbooster.properties
[inputbooster-config] ✓ Config loaded successfully (config version 305)
[Input] Polling thread started at 200 Hz.
[InputBooster] Ready!
```

If you see `Ready!`, the engine, the poller and the mixins are all live. The
lines above it tell you which optional parts applied; the
[log reference](/docs/troubleshooting/log-reference) explains each one.

<Callout variant="warning" title="`Fatal init error!` means the mod is off">
`[InputBooster] Fatal init error! InputBooster is disabled for this session.`
means initialisation threw, the mod disabled itself, and nothing in it will
work. The stack trace above that line is the actual cause. Removing the jar and
re-reading the [common issues](/docs/troubleshooting/common-issues) page is
faster than guessing.
</Callout>

## Where the mod writes

Everything lives next to the game, in the `config` folder:

<FileTree
  title="Files InputBooster creates"
  items={[
    ".minecraft/config/inputbooster.properties",
    ".minecraft/config/inputbooster_profiles.json",
    ".minecraft/config/inputbooster_server_profiles.properties",
  ]}
/>

The `inputbooster.properties` file is created on the first launch with every
default in it. The two other files only appear when you use profiles.

<Callout variant="info" title="Edit the file with the game closed">
The config is written when the settings screen saves and when the client
shuts down. Editing `inputbooster.properties` while the game is running means
your edit can be overwritten at the next save. Close the game first.
</Callout>

## Removing it

Delete the jar. The config files stay where they are, so a reinstall picks up
your old settings. Delete `config/inputbooster.properties` as well if you want
a clean start; the mod recreates it with defaults on the next launch.
