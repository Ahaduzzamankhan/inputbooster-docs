<Lead>
The current interface saves each changed setting immediately. There is no Overview tab or Save & Close button; use the client command to read the current integration and overlay status.
</Lead>

## 1. Open the settings

<Steps>
  <Step title="Open Minecraft Options">
    Press <Kbd>Esc</Kbd> and open Options. Select the InputBooster button.
  </Step>
  <Step title="Use Sodium pages when available">
    On 26.x, a compatible Sodium Config API also exposes General, Features, Overlay and Advanced pages under Sodium Video Settings.
  </Step>
  <Step title="Use Mod Menu if installed">
    The InputBooster Mod Menu entry opens the vanilla fallback screen.
  </Step>
</Steps>

On 1.21.x builds, use the vanilla options button or Mod Menu. Those project trees do not register the Sodium Config API entrypoint.

## 2. Read the status command

Open chat and run:

~~~text
/inputbooster
~~~

The command reports the mod and Minecraft versions, Sodium integration path/status, and overlay state. It does not expose a live Overview tab.

## 3. Check the engine

The engine can run in automatic, event or poll mode. In automatic mode, event hooks are used when they are live and no detected input-routing mod requires fallback. Otherwise the engine polls.

The current compatibility fallback checks Controlify, Midnight Controls, Controllable and Zoomify. Sodium and Iris are rendering mods and do not trigger this fallback.

See [engine modes](/docs/developers/engine-modes) for the exact resolution rules.

## 4. Check the overlay

Open the F3 debug screen. With the default settings, the overlay should appear there. To test its position, run:

~~~text
/inputbooster overlay test
~~~

The command toggles a bright test rectangle. Turn it off again with the same command.

## 5. Change settings

The vanilla screen has six sections: Polling, Input engine, Movement assistance, Click limiter, Overlay, and Safety and feedback. Controls save as they are changed. Sodium's 26.x interface groups the same configuration into four pages.

A few settings remain persisted but have no runtime effect; consult the [key reference](/docs/configuration/keys) before relying on them.

## 6. Confirm the configuration

The main file is <code>.minecraft/config/inputbooster.properties</code>. Confirm that the values you changed are present after leaving the screen. The schema key is currently <code>config_version=305</code>.

<Callout variant="warning" title="Do not use a stopwatch as a benchmark">
The project does not publish a client FPS or latency improvement figure. The internal profiler measures queue-to-drain time inside the mod, not hardware latency or a comparison with vanilla.
</Callout>
