<Lead>
The current settings UI has no Overview or Compatibility tab. Use the HUD overlay for live counters and the client log for hook/fallback decisions.
</Lead>

## 1. Open the overlay

Join a world and open F3. With the defaults, the overlay is visible while the debug screen is open. It shows:

| Line | What it tells you |
| --- | --- |
| Engine | Selected engine mode and current poll rate |
| Events | Keyboard, mouse and submitted-action counters |
| Dispatch | Mean dispatch time and queue depth |

If you want the panel outside F3, set <code>overlay_mode=1</code>. Ensure <code>show_f3_info=true</code> and the vanilla HUD is enabled.

## 2. Confirm the event hooks

Look in <code>latest.log</code> for:

~~~text
[Compat] Keyboard/mouse event hooks are live.
~~~

If this line never appears after pressing a key or mouse button, check the startup mixin lines and the exact Minecraft jar. The current 26.x project has version-signature tests, but a successful build is not a headless client startup test.

## 3. Read the engine mode

The engine can use automatic, event or poll mode. The General Sodium page, or the Input engine section of the vanilla settings screen, exposes the configured mode and compatibility fallback.

| Overlay state | Meaning |
| --- | --- |
| Event | Event hooks have fired and the engine is using event input |
| Poll | The poller is the active source |
| Automatic | The engine chooses based on live hooks and compatibility fallback |

Automatic fallback checks four Fabric mod IDs: Controlify, Midnight Controls, Controllable and Zoomify. Sodium and Iris are rendering mods and do not trigger this fallback. Other input-routing mods may not be detected.

## 4. Compare the counters

The overlay event line reports keyboard events, mouse events and submitted actions.

| Comparison | Likely location |
| --- | --- |
| Keyboard/mouse counters do not rise | The event is not reaching the observer; inspect hook application and focus |
| Input counters rise but submitted actions do not | The event is not mapped to one of the twelve tracked bindings, or no state edge occurred |
| Submitted actions rise | The dispatcher accepted actions; continue to the queue/drainer check |

The counters are cumulative for the session. They are not the number of actions that ultimately succeeded in the game.

## 5. Check the queue

The dispatch line includes queue depth:

| Reading | Meaning |
| --- | --- |
| <code>Queue 0/128</code> | No pending actions |
| Queue near 128 | The drainer may not be keeping up |
| Queue stays full | The drainer may be blocked or failing |

The queue is bounded at 128. A new action is rejected when it is full. Check the log for per-action errors and Safe Mode messages.

## 6. Check drainer preconditions

The game-thread drainer refuses to execute actions when there is no player/game mode, the mod is inactive, Safe Mode disabled the input module, or a screen is open. A screen-open queue clear is intentional: clicks inside a chest or chat belong to that screen.

Look for:

~~~text
[SafeMode] Module 'input' disabled after 5 errors
[InputBooster] ATTACK_PRESSED failed: ...
~~~

## 7. Check the action's own condition

Even a successfully queued action can be ignored when its precondition is false:

| Action | Condition |
| --- | --- |
| <code>ATTACK_PRESSED</code> | Crosshair target is a living entity within vanilla melee reach: three blocks, squared distance 9 |
| <code>USE_PRESSED</code> | Crosshair result is <code>MISS</code>; blocks and entities return to vanilla |
| <code>JUMP_PRESSED</code> | Player is grounded, in water, in lava or climbing |
| <code>FORWARD_RELEASED</code> | Forward key is genuinely up |
| <code>PICK_BLOCK_PRESSED</code> | Crosshair is on a block and the accessor hook applied |

See the [action reference](/docs/reference/actions) for every action.

## Quick checklist

- [ ] Overlay event counters increase when you press a tracked key.
- [ ] The log confirms the keyboard/mouse hooks are live.
- [ ] The engine mode is expected for the installed input mods.
- [ ] Queue depth does not remain at 128.
- [ ] The action's target and state conditions are satisfied.
- [ ] No Safe Mode or per-action failure line appears.
